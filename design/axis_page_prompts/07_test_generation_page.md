# 07. 테스트 생성 페이지 구현 프롬프트

## AI에게 전달할 요청
너는 기존 AXIS 프론트엔드 프로젝트의 공통 레이아웃을 유지하면서 테스트 생성 페이지의 본문만 구현하는 프론트엔드 개발자다. 첨부 스케치에서 이 페이지의 본문은 대부분 비어 있는 큰 캔버스 형태로 표현되어 있다. 따라서 불필요한 정보를 많이 넣지 말고, 생성 작업을 시작하기 전의 워크스페이스와 입력 영역 중심으로 구현한다.

## 페이지 목적
사용자가 분석 대상 또는 인사이트를 기반으로 테스트, 시나리오, 콘텐츠 검증안, 또는 AI 생성 요청을 만드는 페이지다. 아직 생성 전 상태에서는 빈 화면처럼 보이되, 사용자가 무엇을 입력하고 어떤 결과가 생성될지 명확히 안내해야 한다.

## 본문 레이아웃
본문 중앙에는 큰 빈 캔버스를 둔다. 캔버스 중앙에는 `테스트 생성` 제목과 간단한 안내 문구를 표시한다. 상단에는 선택된 대상 정보나 생성 조건을 보여주는 작은 요약 영역을 둘 수 있다. 하단 또는 중앙에는 입력 폼을 배치한다. 입력 폼에는 생성 목적, 대상 기업/키워드, 참고 인사이트, 출력 형식, 난이도 또는 톤을 선택하는 필드가 포함된다.

생성 전 상태에서는 빈 캔버스와 CTA 버튼을 강조한다. 생성 후 상태에서는 같은 캔버스 안에 결과 카드가 나타나도록 한다. 결과 카드는 테스트 제목, 목적, 질문/항목 목록, 평가 기준, 다음 액션을 포함한다. 스케치의 넓은 여백을 유지해 워크스페이스처럼 느껴지게 한다.

## 데이터 매핑
생성 조건은 `generationForm` 객체로 관리한다. 필드는 `target`, `purpose`, `sourceInsightId`, `outputType`, `tone`, `difficulty`, `additionalPrompt`로 구성한다. 생성 결과는 `generatedTest` 객체로 관리하며, `title`, `description`, `questions`, `criteria`, `createdAt`, `status`를 가진다. 기존 인사이트 결과, 카드뉴스, Peer 분석 데이터에서 넘어온 경우 `sourceInsightId` 또는 `sourceContentId`로 원본을 추적한다.

## 상호작용
사용자가 조건을 입력하고 `생성하기` 버튼을 누르면 로딩 상태를 표시한다. 결과가 생성되면 캔버스 중앙에 결과 카드가 나타난다. 사용자는 결과를 `다시 생성`, `저장`, `카드뉴스로 변환`, `보고서에 추가`할 수 있어야 한다. 입력값이 부족하면 버튼을 비활성화하고 어떤 필드가 필요한지 안내한다.

## 디자인 규칙
이 페이지는 비어 있는 공간이 설계 의도다. 과도하게 많은 카드나 차트를 넣지 않는다. 중앙 캔버스는 넓고 정돈된 느낌을 주며, 생성 CTA 버튼만 명확하게 강조한다. 생성 후에도 결과는 하나의 주요 카드로 먼저 보여주고, 상세 항목은 펼침 영역으로 처리한다.

## 완료 기준
공통 헤더와 사이드바는 유지한다. 본문에는 빈 캔버스, 생성 입력 폼, CTA 버튼, 생성 후 결과 카드 상태가 모두 구현되어야 한다. mock 상태로 `empty`, `loading`, `generated` 세 가지 화면 전환이 가능해야 한다.
