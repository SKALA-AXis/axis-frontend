# 03. 매칭 탐색 페이지 구현 프롬프트

## AI에게 전달할 요청
너는 기존 AXIS 프론트엔드 프로젝트의 공통 프레임을 유지하면서, 매칭 탐색 페이지의 본문만 구현하는 프론트엔드 개발자다. 헤더와 사이드바는 그대로 두고, 본문에는 필터와 선택 가능한 카드형 매칭 대상 목록을 배치한다. 스케치에서 보이는 것처럼 상단에 연한 초록색 필터 칩이 있고, 그 아래에 체크 가능한 카드들이 가로로 배치되는 구조를 따른다.

## 페이지 목적
이 페이지는 사용자가 분석 대상, 고객사, 산업군, 콘텐츠 유형, 또는 매칭 후보를 빠르게 탐색하고 선택하는 화면이다. 상세 작업을 하기 전 “어떤 대상 또는 주제를 기준으로 볼 것인가”를 정하는 중간 허브 역할을 한다.

## 본문 레이아웃
본문 상단 왼쪽에는 `필터` 영역을 둔다. 필터는 pill 형태의 연한 초록색 배경으로 표시하고, 클릭하면 조건 패널이 열릴 수 있도록 구조를 준비한다. 필터 바로 아래에는 카드 그리드를 배치한다. 기본 배치는 가로 2~3개 카드이며, 화면 폭에 따라 자동으로 줄바꿈된다. 각 카드는 큰 제목, 짧은 설명, 상태 태그, 체크 표시 영역을 포함한다.

카드는 스케치처럼 넓은 여백을 유지하고, 선택된 카드에는 우측 상단 체크 아이콘 또는 강조 테두리를 표시한다. 카드 예시는 `기업`, `산업`, `키워드`, `콘텐츠`, `담당자`, `기간`과 같은 매칭 기준으로 구성할 수 있다. 실제 서비스 맥락에 맞게 카드명은 기존 도메인 용어로 교체한다.

## 데이터 매핑
카드 데이터는 `id`, `title`, `description`, `category`, `selected`, `updatedAt`, `count` 필드를 가진 배열로 관리한다. 필터 상태는 `selectedFilter`, `searchKeyword`, `sortType`으로 분리한다. 기존 프로젝트에서 사용하던 고객사, 뉴스, DART, Peer, 카드뉴스 데이터가 있다면 이 페이지에서는 “대상 선택용 요약 데이터”만 보여주고 상세 데이터는 다음 페이지에서 로드한다.

## 상호작용
필터를 클릭하면 조건 선택 UI가 열려야 한다. 조건은 산업군, 기간, 데이터 출처, 상태값으로 구성한다. 카드를 클릭하면 선택 상태가 바뀌고, 선택된 카드 기준으로 다음 액션 버튼이 활성화된다. 하단 또는 우측에는 `선택 항목으로 분석 시작`, `상세 보기`, `초기화` 버튼을 배치한다. 검색창 입력값은 카드 목록의 title과 description에 반영되도록 한다.

## 디자인 규칙
전체 톤은 밝은 배경, 얇은 border, 넉넉한 간격을 사용한다. 필터 칩은 스케치처럼 연한 초록색으로 강조한다. 카드 내부는 텍스트가 너무 많지 않게 유지하고, 목록 화면답게 정보 밀도를 낮춘다. 선택 상태는 체크 아이콘, 배경색 변화, border 강조 중 최소 두 가지로 표현한다.

## 완료 기준
공통 레이아웃을 유지하고 본문만 교체한다. 필터, 카드 목록, 선택 상태, 다음 액션 버튼이 모두 존재해야 한다. mock 데이터만으로도 화면이 완전히 렌더링되어야 하며, 추후 API 연동 시 카드 배열만 교체하면 되도록 구현한다.
