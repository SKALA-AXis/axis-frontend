# 02. 배정 페이지 구현 프롬프트

## AI에게 전달할 요청
너는 기존 AXIS 프론트엔드 프로젝트의 공통 레이아웃을 유지하면서, 배정 페이지의 본문 구성만 새로 구현하는 프론트엔드 개발자다. 상단 AXIS 로고, 중앙 검색창, 우측 `L/D`, 채팅, 알림 영역과 좌측 사이드바는 기존 컴포넌트를 그대로 사용한다. 본문은 특정 고객사, 사용자, 담당자, 일정, 이벤트 정보를 한 화면에서 확인하고 우측 대기 목록과 매칭·배정 상태를 관리하는 화면으로 구현한다.

## 페이지 목적
이 페이지는 고객사 또는 분석 대상별로 현재 배정 가능한 항목을 확인하고, 일정·이벤트·상담 맥락을 기준으로 적합한 대상 또는 콘텐츠를 연결하는 작업 화면이다. 스케치의 핵심은 좌측의 상세 맥락 영역과 우측의 대기 리스트 영역을 분리하는 것이다.

## 본문 레이아웃
본문은 좌우 2단 구조로 구성한다. 왼쪽 넓은 영역에는 대상의 기본 조건과 맥락 정보를 표시한다. 상단에는 기간 조건, 예를 들어 `최근 1개월 이상 데이터`, `월 1회 추출`, `분석 가능 상태` 같은 요약 정보를 배치한다. 그 아래에는 두 개 이상의 정보 블록을 둔다. 첫 번째 블록은 상담 또는 일정 정보이며, 고객사명, 담당자, 예정 일정, 최근 접점, 상담 메모를 포함한다. 두 번째 블록은 이벤트 또는 인사이트 근거 영역이며, 고객사 관련 이슈, 최근 뉴스, 내부 기록, AI가 감지한 매칭 사유를 표시한다.

오른쪽 좁은 영역에는 대기 목록 또는 후보 목록을 세로 카드 리스트로 배치한다. 각 카드는 선택 상태를 표시할 수 있어야 하며, 스케치의 체크 표시처럼 선택된 항목은 시각적으로 명확하게 강조한다. 카드에는 후보명, 상태, 우선순위, 마지막 업데이트 시각, 관련 태그를 넣는다.

## 데이터 매핑
왼쪽 상세 영역은 기존 고객사 데이터, 상담 메모, 일정 데이터, 이벤트 로그, 뉴스 요약 데이터와 연결한다. 오른쪽 대기 목록은 배정 후보 또는 매칭 후보 배열을 사용한다. mock 데이터 예시는 `companyName`, `accountOwner`, `scheduleDate`, `recentEvent`, `aiReason`, `candidateStatus`, `priority`, `isSelected`로 구성한다. 실제 API가 확정되지 않은 경우 데이터 구조를 컴포넌트 바깥에 분리해 둔다.

## 상호작용
오른쪽 후보 카드를 클릭하면 선택 상태가 토글된다. 선택된 후보의 상세 근거가 왼쪽 이벤트/근거 영역에 반영되어야 한다. `배정하기`, `보류`, `상세보기` 같은 주요 액션 버튼을 우측 리스트 하단 또는 상세 영역 하단에 둔다. 검색창은 고객사명이나 담당자명 기준으로 후보와 상세 정보를 필터링할 수 있도록 준비한다.

## 디자인 규칙
전체 화면은 스케치처럼 큰 본문 컨테이너 안에 좌측 상세, 우측 리스트가 명확히 구분되어야 한다. 정보 블록은 흰색 또는 연한 회색 카드로 만들고, 선택 상태는 초록색 체크 또는 강조 테두리로 표현한다. 본문 하단에는 필요 시 보조 설명이나 시스템 처리 상태를 작게 표시한다.

## 완료 기준
공통 헤더와 사이드바는 건드리지 않는다. 본문은 좌측 상세 70%, 우측 대기 목록 30% 비율을 기본으로 하며, 작은 화면에서는 우측 목록이 아래로 내려가야 한다. 선택 상태, 후보 데이터, AI 매칭 사유가 컴포넌트 상태 또는 props로 명확히 관리되어야 한다.
